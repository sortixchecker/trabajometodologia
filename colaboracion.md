# 6. Descripción del repositorio y las ramas utilizadas
El proyecto fue almacenado en un repositorio público de GitHub. La estructura del repositorio contiene los archivos problema.md, solucion.md, requisitos.md, planificacion.md, colaboracion.md y reflexion.md, además de una carpeta destinada a las evidencias.

Se trabajó con las siguientes ramas:
* **Main:** rama principal del proyecto.
* **Feature-documentacion:** utilizada por el estudiante para desarrollar la documentación.
* **Feature-colaborador:** utilizada por el compañero para realizar su aporte.

Esta estrategia permitió desarrollar modificaciones de forma independiente antes de integrarlas mediante Pull Requests, siguiendo una práctica recomendada para proyectos colaborativos (Git, 2025).

# 7. Commits y Pull Requests principales
Durante el desarrollo del proyecto se realizaron commits progresivos con mensajes descriptivos para registrar cada avance.

Ejemplos:
* Initial commit.
* Agregar descripción del problema.
* Incorporar requisitos.
* Actualizar planificación.
* Añadir documentación de colaboración.
* Corrección de formato.
* Integración del aporte del colaborador.

# 8. Aporte realizado por el compañero
El miembro del equipo creó una rama literalmente independiente en la que introdujo mejoras en el archivo requisitos.md, haciendo correcciones en la redacción y proponiendo una estructura más visual de la planificación del proyecto. Cuando el trabajo estaba terminado, envió un Pull Request para su revisión. Una vez que los cambios fueron verificados como correctos y acordes a los objetivos del proyecto, la propuesta fue aprobada y los cambios se incorporaron a la rama principal.

# 9. Forma en que se coordinó y revisó la colaboración
La coordinación se realizó mediante comunicación directa entre los miembros. Se acordaron previamente las actividades a desarrollar por cada participante para evitar conflictos de edición. Antes de aceptar el Pull Request se revisaron las modificaciones realizadas por el colaborador, comprobando que no afectaran la estructura del proyecto y que fueran coherentes con la documentación existente.
