| Alta | Elaborar la documentación en archivos Markdown. |
| Alta | Registrar commits descriptivos. |
| Alta | Utilizar ramas para desarrollar cambios. |
| Alta | Gestionar al menos un Pull Request. |
| Media | Resolver un conflicto sencillo o documentar su resolución. |
| Media | Incorporar evidencias del proyecto. |
| Baja | Mantener organizada la estructura del repositorio. |

# 10. Conflicto presentado o procedimiento de resolución
Durante el desarrollo se simuló un conflicto de edición modificando una misma sección del archivo requisitos.md desde dos ramas diferentes.

El conflicto fue identificado durante el proceso de fusión. Para resolverlo se revisaron ambas versiones, se conservaron los cambios correctos y posteriormente se completó la fusión manualmente, manteniendo un historial consistente del proyecto. Este procedimiento corresponde al flujo habitual de resolución de conflictos en Git (Chacon & Straub, 2023).
